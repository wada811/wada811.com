date: 2026-10-01

---

Claude Code に `cd` を含むコマンドを実行させていたら、関係のないはずのディレクトリ一覧が結果に混ざるようになった。原因は、人間用に書いていた zsh の設定だった。

AI コーディングエージェントが裏で動かす非対話シェルは、人間向けに書かれたシェル設定を思わぬ形で実行してしまうことがある。同じ種類の事故は、他のツールや他の dotfiles でも起こりうる。

## 起きたこと

Claude Code に `cd ディレクトリ && コマンド` を実行させると、結果の先頭に見覚えのないファイル一覧がつくことがあった。頼んでいないのに、移動先のディレクトリの中身がずらりと並ぶ。実際に数えてみると、Bash の実行結果5,104回のうち1,660回、割合にして33%がこの状態だった。

## zsh の chpwd フック

原因は zsh の `chpwd` という仕組みだった。`chpwd` はカレントディレクトリが変わるたびに自動で呼ばれる関数で、名前を付けて定義するだけでシェルに登録される。手元の設定では、この `chpwd` に `ls_abbrev` というディレクトリの中身を表示する関数を仕込んであった。`cd` するたびに移動先の一覧が自動で見える、ターミナルの便利カスタマイズである。

## 対話シェルと非対話シェルの境界

この便利機能は、人間がターミナルで打ち込んでいるときだけ効けばよいものだった。ところが Claude Code の Bash tool は、コマンドを実行するために非対話シェル（人がキーを打たずに裏で動くシェル）を起動する。この非対話シェルも、対話シェルと同じ `.zshrc` を読み込む。対話か非対話かを区別せずに全シェルで読まれるファイルの中に、対話専用のつもりの設定を書いていたのが見落としだった。

## 登録そのものを条件にする

最初に思いついた直し方は、`chpwd` の中身に「非対話なら何もせず戻る」という判定を足すことだった。

```zsh
chpwd() {
    [[ -o interactive ]] || return
    ls_abbrev
}
```

これでも動く。しかし関数は非対話シェルでも定義されたままで、`cd` のたびに判定だけは毎回走る。より筋が良いのは、対話シェルのときだけ `chpwd` という関数そのものを定義することだ。

```zsh
if [[ -o interactive ]]; then
    chpwd() {
        ls_abbrev
    }
fi
```

`-o interactive` はシェルが起動した時点で決まる値で、`.zshrc` を読み込む時点ですでに確定している。定義する時点で一度だけ判定すれば十分で、非対話シェルでは `chpwd` という関数自体が存在しなくなる。

## 他のツールにも起きうること

AI エージェントが裏でシェルを起動する機会は、今後も増えていくはずだ。「人間向けの対話的な装飾」と「対話か非対話かを問わず読まれる設定ファイル」を同じ場所に書いている限り、同じ見落としは他のツールや他の dotfiles でも起きる。
